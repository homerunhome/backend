# 백엔드 기능 구현

1. 관련 API 계약과 문서, 기존 패키지·테스트 구조를 확인합니다.
2. 변경 범위와 제외 범위, 영향받는 API·데이터·테스트를 정리해 공유합니다.
3. 구현 방향을 먼저 제안하고 승인받은 뒤 코드 변경을 시작합니다.
4. 현재 프로젝트의 구조를 따르며 필요한 책임만 최소한으로 나눕니다. 아직 사용하지 않는 계층이나 추상화를 미리 도입하지 않습니다.
5. 요청·응답 경계와 핵심 비즈니스 규칙을 분리하고, 기존 예외·응답 형식이 있으면 재사용합니다.
6. 비즈니스 규칙과 예외 상황을 우선 테스트합니다. HTTP 경계·DB 동작 테스트는 실제 검증 가치와 현재 의존성에 맞춰 추가합니다.
7. 외부 API는 실제 서버에 의존하지 않도록 테스트 대역을 사용합니다. 이를 위해 새 의존성을 추가해야 한다면 필요성을 먼저 확인합니다.
8. 단순 DTO, 기본 CRUD, Repository 호출만 전달하는 코드에는 불필요한 테스트를 추가하지 않습니다.
9. `./gradlew test`를 실행하고, PR 전 `./gradlew clean build`를 실행합니다.

승인받지 않은 범위의 기능·리팩터링, Controller에 비즈니스 로직 추가, 민감정보 노출, 실패 테스트 삭제·비활성화, 검증 우회는 하지 않습니다.

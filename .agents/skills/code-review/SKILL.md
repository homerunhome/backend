# 코드 리뷰

1. 승인된 구현·제외 범위와 실제 diff가 일치하는지 확인합니다.
2. 기존 API 계약, 코드 구조, 네이밍과 호환성을 확인합니다.
3. 요청받지 않은 기능, 불필요한 추상화·리팩터링이 없는지 확인합니다.
4. Controller, Service, Domain, Repository의 책임이 뒤섞이지 않았는지 확인합니다.
5. 예외·응답·로그가 기존 규칙을 따르고 민감정보를 노출하지 않는지 확인합니다.
6. 테스트가 비즈니스 로직과 예외 상황을 검증하고, 단순 위임 코드에 과도하게 추가되지 않았는지 확인합니다.
7. `./gradlew test`와 PR 빌드 검증이 누락되지 않았는지 확인합니다.

결과는 치명도 순서로 정리하고, 근거 없는 스타일 선호는 지적하지 않습니다.
